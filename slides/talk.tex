\begin{frame}[fragile]{The check passed. The parser was still broken.}
\begin{lstlisting}
mutable checker       PASS
parser artifact       unchanged

external case "1,,3"   REJECT expected
actual parser output  [1, 3]
\end{lstlisting}
\subline{One result from the lab. We will come back to how it happened.}
\evidence
\note{Pause after the first line. This is a measured outcome of our synthetic lab. The worker replaced its checker with a process that exits zero, leaving the buggy parser unchanged. The independent case still catches the bug. This opening introduces the strongest consequence: the system can be wrong about success. Work backward through the authority it granted.}
\end{frame}

\begin{frame}{One job. Four independent experiments.}
\bigline{Fix the parser.\\Publish the task report.}
\vspace{4mm}
\subline{Fresh fixtures for each experiment. Same operator intent.}
\vspace{3mm}
\textcolor{acid}{Identity}\hspace{4mm}
\textcolor{acid}{Files}\hspace{4mm}
\textcolor{acid}{Data release}\hspace{4mm}
\textcolor{acid}{Acceptance}
\note{The parser should accept comma-separated integers and reject empty fields. The agent needs task input, somewhere to write a patch, and a narrow report operation. Each experiment starts with its own fixtures. They are independent failure paths, not a four-step intrusion and not a customer incident.}
\end{frame}

\begin{frame}{What the experiment assumes}
\textcolor{alarm}{Worker controls:} its code, workspace and requests.

\textcolor{acid}{Controller owns:} launch policy, service permissions, verification and publication.

\subline{Synthetic credentials and data. A loopback service. No live model or external target.}
\evidence
\note{We begin after an adversarial action has been chosen. This makes enforcement reproducible. Isolated mode uses Linux user, PID and mount namespaces through bubblewrap, with a separate network namespace where specified. The service and controller remain outside the worker. Reference mode does not establish those boundaries. Read the evidence label honestly.}
\end{frame}

\begin{frame}[fragile]{01 / The worker borrowed the runner's identity}
\begin{lstlisting}
request: GET /projects/other/private

runner credential     200 + synthetic fixture
task credential       403
task input            200
expired credential    403
\end{lstlisting}
\subline{The service decides what the credential authorizes.}
\evidence
\note{The weak launcher passes a synthetic broad runner token into the child. It reads another project even though its task ID says parser-fix. The repaired launcher projects a task-scoped token. Repeat the identical forbidden request and the service refuses it. Then read task input successfully. Expiry and wrong-audience checks also run. Our local service uses an in-memory grant table rather than implementing OAuth.}
\end{frame}

\begin{frame}{Identity follows an explicit grant}
\textcolor{acid}{Launch:} clean environment and closed extra descriptors.

\textcolor{acid}{Grant:} task resource, operation, audience and expiry.

\textcolor{acid}{Enforcement:} a service or broker outside the worker.

\subline{A stronger process boundary still needs narrower credentials.}
\note{Ask what the child inherits before asking what the model intends. A short-lived token retains all its permissions until expiry. Keep broad upstream credentials outside the worker and project only the required capability. This finite lab demonstrates service-side scope, audience and expiry decisions. References: Linux environ(7) and RFC 9700.}
\end{frame}

\begin{frame}[fragile]{02 / The mount reached the next job}
\begin{lstlisting}
worker writes /shared/next-job.json

writable bind   host fixture changes
read-only bind  write denied; fixture unchanged
/output         patch remains writable
\end{lstlisting}
\subline{\mountscope}
\note{Use a next-job queue fixture, separate from the verifier. This keeps filesystem and acceptance failures distinct. The attack is an ordinary write to a deliberately mounted path. In isolated mode the controller checks host bytes, resets the fixture, removes the prior output, and reruns with a read-only bind. Reference mode skips this entire integration experiment.}
\end{frame}

\begin{frame}{Filesystem access is part of the task contract}
\begin{tabular}{@{}ll@{}}
\color{acid}Resource & \color{acid}Worker access\\[9pt]
Source input & Read only\\[9pt]
Task output & Writable\\[9pt]
Shared job state & Read only in this lab\\[9pt]
Controller files & Outside the mount set
\end{tabular}\par
\vspace{4mm}
\subline{Production deployments can omit shared state entirely.}
\note{The host constructs the mount set. A path check in code the worker can edit cannot enforce it. Our repaired demonstration keeps the same fixture visible but read-only for a direct comparison. Omit it when the task does not need to read it. Read-only access still permits disclosure. Reference: Docker bind-mount documentation.}
\end{frame}

\begin{frame}[fragile]{03 / The service was allowed. The recipient was wrong.}
\begin{lstlisting}
same upload service

/accounts/team/reports    intended recipient
/accounts/other/uploads   synthetic private data
\end{lstlisting}
\subline{The weak worker reaches a second account on the same service.}
\evidence
\note{Both paths are on the same loopback endpoint. The fixture models a multi-tenant service with an available upload capability for each account. We verify that the receiving service stores the synthetic canary under the other account. A network destination and a data recipient are different policy choices. This is a local example, not a claim about a vendor.}
\end{frame}

\begin{frame}{Data release needs a narrow operation}
\textcolor{acid}{Worker:} requests one fixed report operation.

\textcolor{acid}{Broker:} constructs the body and selects the team account.

\textcolor{acid}{Checks:} rejects extra recipient, payload and URL fields.

\subline{\networkscope}
\note{The worker emits a request on stdout. The controller treats it as untrusted input, accepts one exact schema, and constructs the report from controller-owned fields. Isolated mode gives the worker a new network namespace and tests reachability of the host loopback service. Arbitrary report strings would reopen a data channel. This operation does not establish universal freedom from covert channels.}
\end{frame}

\begin{frame}[fragile]{04 / The worker changed what success meant}
\begin{lstlisting}[language=Python]
# Worker rewrites the workspace checker:
print("PASS")
raise SystemExit(0)
\end{lstlisting}
\subline{The old controller accepts exit code zero. The parser stays broken.}
\evidence
\note{Return to the opening. The vulnerable controller executes a workspace checker the worker can replace. File mutation is the mechanism, but the security failure is who owns acceptance. The repaired controller never delegates expected results or its decision to that checker. It executes candidate code as a worker and compares output outside that worker.}
\end{frame}

\begin{frame}{The same artifact meets an independent verifier}
\begin{tabular}{@{}lll@{}}
\color{acid}Input & \color{acid}Buggy parser & \color{acid}Fixed parser\\[8pt]
\texttt{1,2,3} & Accept & Accept\\[8pt]
\texttt{1,,3} & \textcolor{alarm}{Accept} & Reject\\[8pt]
Empty input & \textcolor{alarm}{Accept} & Reject\\[8pt]
\texttt{-2, 3} & Accept & Accept\\[8pt]
\texttt{x} & Reject & Reject
\end{tabular}\par
\evidence
\note{The controller snapshots exact parser bytes after the producer exits. It runs those bytes in a separate worker per case and compares output with controller-held expected results. The buggy parser fails two cases. The fixed parser passes five. Candidate code never executes inside the controller process. Five cases show this defect and repair; they do not prove complete parser correctness.}
\end{frame}

\begin{frame}{Acceptance belongs to exact bytes}
\begin{tabular}{@{}ll@{}}
Rejected artifact & Denied\\[7pt]
Artifact swapped after verification & Denied\\[7pt]
Authentic approval from a stale run & Denied\\[7pt]
Verifier identity changed & Denied\\[7pt]
Replayed approval & Denied\\[7pt]
Verified artifact, current run & \textcolor{acid}{Accepted}
\end{tabular}\par
\evidence
\note{The controller authenticates an approval binding artifact digest, run, verifier source digest, policy and a single-use nonce. Its MAC key remains outside worker mounts and environment. We separately test a stale run with the same key, changed verifier identity, forged approval, substituted artifact and replay. The lab gate returns a publication decision; it does not deploy software externally.}
\end{frame}

\begin{frame}{History needs an independent anchor}
\bigline{The worker can rebuild\\a chain it owns.}
\vspace{4mm}
\subline{The controller retains the original head. Rewritten history disagrees.}
\evidence
\note{Change a failed verification event to success and recompute every subsequent link. The chain differs from the controller-held head. This demonstrates the need for a reference outside attacker control. The lab reference lives in controller memory, not durable transparency infrastructure. History provides evidence of rewriting. The verifier and gate enforce acceptance.}
\end{frame}

\begin{frame}{The original job still succeeds}
\begin{enumerate}
\item Worker reads input and writes the fixed parser.
\item External verifier checks the frozen artifact.
\item Gate accepts exactly those bytes.
\item Broker publishes the fixed task report.
\end{enumerate}
\vspace{3mm}
\subline{\evidencecount}
\evidence
\note{This is the positive end-to-end control. In isolated mode the worker has read-only input, writable task output, no projected service credential and a separate network namespace. Publication and reporting happen only after external verification. The parser fix is deterministic fixture code, not live model output. Reference mode runs the sequence without isolation and must be described that way.}
\end{frame}

\begin{frame}{Four boundaries to inspect}
\begin{tabular}{@{}ll@{}}
\color{acid}Question & \color{acid}Enforcing owner\\[9pt]
What can execute and reach the host? & Runtime\\[9pt]
What can read and change files? & Host mount policy\\[9pt]
What can act and send data? & Service and broker\\[9pt]
What can declare success? & Verifier and gate
\end{tabular}\par
\note{Map every permission to a component that can refuse the action outside worker control. Execution isolation is the foundation. Filesystem, credential, egress and acceptance policies govern granted authority. A microVM changes the execution boundary but does not automatically narrow a token, destination or acceptance decision.}
\end{frame}

\begin{frame}{Appendix / Limits of the evidence}
Deterministic scripts exercise chosen actions.

Namespace and mount checks require the isolated run.

Five parser cases establish one demonstrated repair.

Controller code, keys and decisions remain trusted.

\subline{No cgroup, kernel-exploit, covert-channel or universal security claim.}
\note{Do not imply we measured model susceptibility to prompt injection or proved the absence of all sandbox escapes. The controls address named failure paths. The network probe targets the fixture endpoint. The history anchor is ephemeral. Production hardening and broader adversarial analysis remain separate engineering work.}
