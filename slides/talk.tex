\renewcommand{\track}{04 / ROOT CAUSE}
\begin{frame}[t]
% title: A read-only checker is not a read-only judge
% time: 03:55-04:55
% cue: Introduce the transitive closure. This is the core line.
% source: https://github.com/zozo123/nyc-talk/blob/main/factory/core.py
\frametitle{A read-only checker is not a read-only judge}
\vspace{3mm}
\begin{columns}[T,onlytextwidth]
\begin{column}{.48\textwidth}\kicker{WHAT YOU LOCKED}{\fontsize{20}{24}\selectfont checker.py\par}\scope{Protected bytes. Correct mount. No overwrite.}\end{column}
\begin{column}{.48\textwidth}\kicker{WHAT JUDGED YOU}{\fontsize{20}{24}\selectfont checker + reads + calls\par}\scope{The transitive closure includes agent-writable inputs.}\end{column}
\end{columns}
\vspace{6mm}
{\fontsize{18}{22}\selectfont\bfseries The judge is the checker plus everything it reads and any code it executes.\par}
\takeaway{Locking one executable does not lock the decision.}
\note{This is the root cause. A checker is a file. A judge is a computation. If the checker reads a golden file, policy file, snapshot, test manifest, or route table, those bytes are part of the judge. If it imports candidate code, that code is part of the judge. The security boundary is the full closure that can say yes. Audit that closure, not the filename. Once you see the closure, the fix stops being mystical: remove worker ownership from every byte in it.}
\end{frame}

\renewcommand{\track}{09 / VERIFIER}
\begin{frame}[t,fragile]
% title: The repaired verifier binds criteria before the worker runs
% time: 09:00-10:00
% cue: Make this boring and mechanical. Boring is the point.
% source: https://github.com/zozo123/nyc-talk/blob/main/factory/core.py
% source: https://github.com/zozo123/nyc-talk/blob/main/evidence/isolated-factory.json
\frametitle{The repaired verifier binds criteria before the worker runs}
\begin{lstlisting}
criteria_digest = sha256(expected_json)
run_worker(candidate_dir, writable=True)
run_checker(candidate, criteria_digest, readonly=True)
verdict = sign(candidate_digest, criteria_digest, observations)
\end{lstlisting}
\vspace{3mm}
{\fontsize{13}{16}\selectfont Re-run with controller-owned criteria:\\broken candidate is \textcolor{warn}{REJECTED}; real fix is \textcolor{acid}{ACCEPTED}.\par}
\takeaway{The worker can write code. The controller owns what counts.}
\note{The verifier fix is boring on purpose. Hash the criteria before the worker runs. Run the worker in its writable space. Then run the checker against controller-owned criteria, not workspace-owned criteria. The verdict signs the candidate digest, criteria digest, and observations together. When we do that, the unchanged broken program is rejected and the real fix is accepted. Boring protocols survive automation. A clever model can search policy wording, but it cannot rewrite a digest that the controller already bound before the search began.}
\end{frame}

\frametitle{The invariant is a small theorem about who may write the judge}

{\fontsize{15}{19}\selectfont Let \textcolor{acid}{J} be every byte and callable that can affect verdict.\par}
\vspace{4mm}
{\fontsize{18}{22}\selectfont\bfseries If the worker can write \textcolor{warn}{J} before verdict, the worker can search for a verdict instead of a fix.\par}

If the worker can write J before the verdict, the worker can optimize for the verdict instead of the fix. The necessary invariant is not that the sandbox is strong. It is that J is outside-owned, content-bound, and replay-safe at the moment it judges the work. That turns agent security into an ownership proof over the verdict path.}
\end{frame}
